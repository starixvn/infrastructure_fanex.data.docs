    Introduction

    Fanex.Data - A Dapper-based data access library with configurable stored procedure names.

    Fanex.Data is a lightweight data access library built on top of Dapper, extending its capabilities with configurable stored procedure names via an SpNames.xml file. This key feature is especially useful for managing different versions of stored procedures, allowing you to easily configure your application to call specific versions like xtest, xpre, or UAT stored procedures, even within a production environment. By centralizing the configuration of stored procedure names, Fanex.Data improves maintainability and provides a flexible solution for both SQL Server and MySQL, all while leveraging Dapper's high performance and simplicity.

    Package Purposes:

    • Fanex.Data
      • The core library simplifies data access by leveraging Dapper. It centrally manages stored procedure names and connections through configuration files.
    • Fanex.Data.Repository
      • Introduces the DynamicRepository class, a simplified wrapper for Fanex.Data's ObjectDb. It provides a more straightforward interface for basic database operations, making it an ideal choice for quick and simple data access needs.
    • Fanex.Data.MySql
      • The MySQL-specific implementation of the Fanex.Data library
    • Fanex.Data.SqlServer
      • The SqlServer-specific implementation of the Fanex.Data library

    Key Features

    • Execute a stored procedure returning data sets then map them to strongly typed lists.
    • Extend ADO.Net CRUD functionalities working with stored procedures.
    • Anonymous objects, strongly type objects, or IDictionary typed objects can be used as parameter sets to set values to stored procedure's parameters.
    • Automatically assign values of OUTPUT parameters back to the parameter sets; which can be anonymous objects, strongly type objects, or IDictionary typed objects.
    • Wrap any exception occurred with diagnostic information, such as: stored procedure name, parameters which are used in the execution, connection string, etc.
    • Avoid throwing exceptions if number of values does not meet number of parameters listed in stored procedure definition.
    • Allow developers to:
      • Configure connection strings and connection aliases.
      • Map between columns of result set and objects' properties.
      • Define firm parameters, parameters which their values are set in configuration files.
      • Configure execution timeout.
      • Etc.
    • Provide ways to extend its functionalities by implementing cross-cuttings, custom connection string providers, or custom setting providers.
